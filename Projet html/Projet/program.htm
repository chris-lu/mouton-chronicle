Ce jeu a ete devellope en C et en assembleur pour environnement DOS a l'aide de Borland 4.52.

La programmations a ete faite par etapes successives avec un ajout pemanents d'elements nouveaux.

Le principal probleme sous l'environnement DOS est la memoire ( Limite a 640 Ko (10 pages de 64Ko) qui est souvent deja en partie utilisee par d'autres programmes) car celui-ci travail en Mode reel. Le but a donc ete de faire un jeu beau, amusant, et interessant, tout ceci utilisant moins de 580 Ko de memoire.. Plusieurs solutions aurait pus etres utilises pour resoudre ce probleme :

  • Tout d'abord, La memoire paginee ou encore la memoire etendue. Cependant l'acces a cette memoire est relativement lent par rapport a la memoire convetionnelle. Cette solutions a donc ete mise de cote.
  • Optimisation de code a l'aide de l'assembleur : Plus rapide, plus petit mais plus difficile. (Solution retenue).
  • Les Dos-Extenders ( Comme DOS4GW.exe pour le compilateur Watcom C++) permet la traduction d'un programme developper en mode reel en un programme exploitant les capacites du mode protege(4 Go de memoire adressable) sans aucune modifications dans le code du programme original. Or aucun Dos-Extander pour Borland n'a ete trouve (ou ne fonctionne) a ce jour.
  • Limiter les graphismes ou le code ( donc les possibilites du jeu ). Cette solutions n'est ni avantageuse pour nous, ni pour vous !
  • Programmer tout simplement en mode protege! Oui mais non.... Car les variantes du mode protege (poiteurs, fonctions, etc...) me sont inconues et l'apprantissage de la programmation graphique peut se reveler tres longue....

La programmation sous dos necessite aussi une reprogrammation complete des element de base (deja programmes sous windows par exemple...) comme le lecteur de CD Audio, le clavier, l'affichage, etc.....

Une tres grande partie des procedures a ete programmee personnellement. La minorite restante a ete retravaillee pour les besoins du programme( compatibilite et rapidite). AUCUNE PROCDURE (ou peut etre une seule (???) ) OU FONCTION N'A ETE REPRISE ENTIEREMENT.

Les bases du langage C++ ont ete aprisent pour la creation de l'autorun.

Le reste des problemes ont ete moins importants ( mais cependant tres nombreux ) et ont pu etre resolus avec un peu d'imagination, de reflexion et de documentation (Livre : Programmation systeme PC ).

Le jeu a ete programme de façon a ce qu'il soit le plus intuitif possible avec la possibilite de cree facilement ses propres niveaux, etc...

 

Quelques chiffres :

  • 7 pages graphiques maximum de 64000 octets pour l'affichage (438 Ko)
  • Fichier executable contenant les variables et le code (109 Ko)
  • Memoire restante utilises pour les diverses donnees : < 23 Ko
  • Memoire totale : < 580 Ko
  • Lignes de code > 5200
  • Nombre de caracteres > 128 000
  • Temps de travail total > 80 H
